# 02 — Transformation Roadmap

## Guiding Sequence

The program followed a simple order: stabilize critical services, create visibility, standardize, automate, then optimize.

## Phase 1 — Stabilize

- Establish one support and escalation path.
- Recover access to critical vendor and telecom portals.
- Document high-impact services and site dependencies.
- Resolve urgent connectivity, voice, endpoint, and access problems.
- Introduce a consistent ticket or email record for requests.

## Phase 2 — Establish Visibility

- Build a common inventory data model.
- Map users, devices, locations, subscriptions, and vendors.
- Deploy remote monitoring and management in controlled waves.
- Create management dashboards and regular review reports.

## Phase 3 — Standardize

- Define role-based hardware and software standards.
- Create repeatable onboarding, offboarding, procurement, and outage workflows.
- Separate technical ownership, financial approval, and operational accountability.
- Define baseline security and configuration requirements.

## Phase 4 — Automate and Secure

- Automate workstation provisioning and common validation tasks.
- Standardize macOS deployment through MDM.
- Deploy endpoint protection and monitoring.
- Improve email, group, access, and account-lifecycle controls.

## Phase 5 — Optimize

- Consolidate duplicate services and unused licenses.
- Reduce avoidable travel through reliable remote workflows.
- Review telecom, print, and recurring service contracts.
- Use monthly metrics to select the next improvement cycle.

## Prioritization Model

Each initiative was scored across five dimensions:

1. Service and clinical impact
2. Security and privacy risk
3. Number of users or locations affected
4. Implementation effort and dependency risk
5. Ongoing operating cost

This prevented high-visibility but low-impact requests from displacing essential foundational work.
