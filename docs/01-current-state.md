# 01 — Current-State Discovery

## Objective

Build a reliable picture of the environment before choosing products or making large changes.

## Discovery Areas

| Area | Questions |
| --- | --- |
| Locations | How many sites exist, and which services are critical at each one? |
| Endpoints | What devices exist, who uses them, and how are they managed? |
| Identity | Where are accounts created, changed, reviewed, and removed? |
| Network | Who provides connectivity, and what equipment and support paths exist? |
| Telecom | Which numbers, extensions, call flows, and contracts are active? |
| Applications | What is installed, licensed, approved, or unsupported? |
| Security | Which controls are consistent, missing, or impossible to verify? |
| Vendors | Who owns each relationship, renewal, escalation, and technical decision? |
| Processes | Which recurring tasks depend on memory or one individual? |

## Method

1. Interview operational owners and site managers.
2. Visit representative locations and validate records physically.
3. Consolidate inventories into one data model.
4. Identify critical services and single points of failure.
5. Rank gaps by patient-service impact, security exposure, effort, and cost.
6. Present findings as decisions, not as a raw device list.

## Typical Findings

- Multiple equipment standards for the same job role
- Incomplete ownership and lifecycle records
- Support that requires unnecessary travel
- Duplicate or unused licenses and services
- Inconsistent endpoint protection and update status
- Critical knowledge stored in email or with individual staff members
- Purchasing decisions made without a documented technical standard

## Deliverables

- Current-state summary
- Risk and dependency register
- Asset and service baseline
- Location priority matrix
- Ninety-day stabilization backlog
- Longer-term transformation roadmap

The discovery phase is complete only when leadership can understand the risks and choose priorities without reading technical logs.
